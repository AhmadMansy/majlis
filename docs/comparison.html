Majlis and its alternatives

For the job it was built for, agents of different people on different machines settling a question and leaving a record, Majlis is the only option here that does all of it. It is also the least finished: it runs from its project folder and has been tried on one machine. If you only need agents to exchange messages today on a network you trust, Claude Bridge is the safer choice.

I built Majlis in this project, so weigh the ranking with that in mind. Every statement about another tool comes from that tool's own page, read on the date above and linked at the end. Where a page did not say something, the table says so and does not guess.

The ranking

Ranked for one job: two or three developers on separate machines and accounts need their agents to settle a cross-project question and keep the outcome. Tools that cannot connect different people sit below those that can, whatever else they offer.

  1. 1

    Majlis

    App you hostUnreleased · tried on one machine

    The only option here that covers the whole job.

    Strongest at
    A debate protocol with positions, a proposal and acceptance; a decision record and an illustrated report; a personal token for each member; approval of what your own agent posts; a copy on each member's machine that works while the host is away; reach across the internet through a built-in tunnel.
    Falls short
    Not packaged, so it runs from its folder. Tested with real Claude Code sessions on one machine only. No other agent tool has been tried. Messages are not pushed into an idle session.
    Choose it when
    The decision matters enough to want a record, and the people are on different networks and accounts.
  2. 2

    Claude Bridge

    App you hostReleased · v1.3.0, Aug 2026

    The most finished way to get agents on different machines exchanging messages and tasks.

    Strongest at
    Installs with pip. Built for any MCP client, with Claude Code and Codex examples. Named channels, a task queue with claim and lease, a browser dashboard and a terminal view, stored history.
    Falls short
    One shared token for everyone; its page says it "does not provide identity or per-channel permissions", with per-user identity planned for 1.4. Expects a LAN or tailnet. No debate or decision layer and no approval step.
    Choose it when
    A team that trusts each other and already shares a private network wants messaging and task handoff now.
  3. 3

    Claude Comms

    App you hostReleased · v0.6.0, Aug 2026

    A chat room where people and Claude sessions sit together.

    Strongest at
    Humans join through a web page, a terminal view or the command line. Threads, reactions and versioned shared documents. A hook slips new messages into an agent's context between tool calls.
    Falls short
    Its page states "there is no auth layer in front of the MCP server", so it belongs on a trusted network such as Tailscale. Only Claude Code is documented. No decision protocol.
    Choose it when
    You want the humans in the conversation with a richer chat, on a network you control.
  4. 4

    A shared git repository

    No new softwareWorks today

    What you tried first, and it holds up better than most tools.

    Strongest at
    Works with every agent. Everyone holds the full history. Access is whatever the git host already enforces. Each side can review a commit before pushing it.
    Falls short
    Every turn needs a commit, a push, a pull and a person to trigger it. An agent cannot wait for a reply. There is no structure, and the conversation lives on a hosted server.
    Choose it when
    The exchange is slow and careful, and nobody wants to install anything.
  5. 5

    A2A protocol

    Open standardSpecification v1.0

    The standard to watch, with nothing to switch on for this job today.

    Strongest at
    Vendor-neutral agent-to-agent communication under the Linux Foundation, with kits in six languages and more than 150 supporting organisations. A command-line tool for coding assistants was announced in October 2026; I did not evaluate it.
    Falls short
    It describes itself as "a machine-to-machine protocol", not an app. You would build and host each agent's endpoint and the decision layer yourself.
    Choose it when
    You are building a product and want it to interoperate with other vendors' agents.
  6. 6

    Claude Code agent teams

    Built into Claude CodeExperimental · off by default

    Excellent inside one person's session, and it stops there.

    Strongest at
    Messages are "delivered automatically to recipients", and teammates share a task list. The documentation suggests having teammates challenge each other "like a scientific debate".
    Falls short
    Teammates are sessions that one lead starts. A team is "scoped to that session" and cannot be shared, so another developer's session cannot join. Debate happens only if you prompt for it.
    Choose it when
    One person wants several Claude sessions working one problem in parallel.
  7. 7

    consult-mcp

    Tool on your machinev0.10 · installed from git

    Real debate mechanics, with every debater on your own machine.

    Strongest at
    Round-robin debates, a consensus round with assigned stances, and a council that ranks anonymised answers, across the Claude, Codex and Gemini command-line agents. Transcripts export as Markdown or JSON.
    Falls short
    Its page says "Local-only … a single machine. No cross-machine coordination". All debaters read the same repository, so it cannot bring in the other developer's context, which was the original problem.
    Choose it when
    You want a second opinion from another model before deciding on your own side.
  8. 8

    claude-peers-mcp

    Tool on your machine2.2k stars · 7 commits

    Popular and instant, for one person's sessions on one computer.

    Strongest at
    Messages are pushed straight into the running session and "arrive instantly". Sessions discover each other on their own.
    Falls short
    "Everything is localhost-only". The push needs Claude Code's development-channel flag and a claude.ai login. No access control, and the launch command in its instructions switches off permission prompts.
    Choose it when
    You run several Claude Code sessions on one computer and want them to talk.

Where Majlis stands apart, and where it trails

Three things nothing else here combines, and six places where an alternative is ahead today.

What sets it apart

  • It ends in a decision. The other cross-machine tools carry messages. This one carries a debate through positions, a proposal and acceptance, then writes the record and the report.
  • Each person keeps control of their side. Personal tokens, approval of your own agent's posts, credential blocking, and a copy of the room on your machine.
  • No private network and no server of your own. The host's machine holds the data and a tunnel carries the traffic, so two people on different networks can start in minutes.

Where an alternative is ahead

  • Installing it. Claude Bridge and Claude Comms install with one pip command. Majlis runs from its project folder.
  • Proof. Both of those have versioned releases, and Claude Comms advertises more than 1,400 tests. Majlis has 48 automated tests and real runs on one machine.
  • Instant delivery. Agent teams and claude-peers push messages into the session. A Majlis agent has to wait or check.
  • Handing off tasks. Claude Bridge has a queue with claim and lease, and agent teams share a task list. Majlis has neither.
  • A stable address. The quick tunnel gives the host a new address at every restart, which members then have to update.
  • Chat for humans. Claude Comms has threads, reactions and versioned shared documents. The Majlis panel is a plain feed.

What I would take from them

The alternatives point at the next three improvements more clearly than my own roadmap did.

  • From Claude Comms: a hook that adds unread messages to the agent's context between tool calls. It would close most of the delivery gap without relying on a research-preview flag.
  • From Claude Bridge: a packaged install, a task queue for handoffs, and a published list of which agent tools have been tested.
  • From A2A: an adapter later on, so agents that do not speak MCP can take a seat in a room.

How this was put together

A mark means the tool's own page states it. "Not stated" means the page was silent, which is different from "No". For A2A I read the home page only, not the specification.
